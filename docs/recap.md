# docs/recap.md — Weekly recap (weekly_recap.py)

> Loaded on demand from CLAUDE.md. Read when editing `weekly_recap.py`. Rules here are as authoritative as CLAUDE.md.

**`weekly_recap.py`** reads the same snapshot on Mondays, builds a full-league recap HTML email: Week N Highlights · My Matchup (full 12-cat table) · Lineup Efficiency (`build_lineup_efficiency`) · League Scoreboard (all 6 matchups) · Weekly Roto Rankings · Top Performers (rostered + hot FAs, hitters/pitchers side-by-side via `_two_col`) · Standings & Luck · Season Trajectory · **Season Roto Rankings** (`build_season_roto_rankings` — heat-mapped 12-cat grid aggregated over EVERY matchup: teams **ranked** by cumulative `Roto_Score`, **displayed** value = the true season-to-date stat from ESPN's cumulative `mTeam` view (`season_cat_totals`), NOT a sum/average of weekly values. Ranking and value are independent by design — for rate cats {OPS,ERA,WHIP} the season stat can't be recovered by averaging weekly values; falls back to the summed/averaged weekly value only when a season total is missing). **Imports `send_digest`** for all shared code (colors/styles, `_n`/`_fmt_refresh_time`/logos/`band_divider`/`section_head`/`luck_standings`/`send_email`, and the season Trajectory + Roto Rankings builders — the old hand-copied versions had already drifted and are deleted); only recap-specific rendering lives here. Output: `previews/recap_week_N.html`. GitHub Actions: `.github/workflows/weekly-recap.yml` (Monday 15:30 UTC).

**`build_commissioner_story`** (`weekly_recap.py`) — Week N Highlights at the top of the recap. Two-column: commissioner prose (left, 60%) + stat sidebar (right, 40%). Finds (a) weekly roto winner, (b) hitter of week (rostered, best OPS, min 10 AB from `prev_week_hitting`), (c) pitcher of week (rostered, **K-first** ranking, min 8 IP from `prev_week_pitching`), (d) FA batter of week (best OPS among free agents), (e) FA pitcher of week (K-first among free agents), (f) a league-wide **"Matchup of the Week"** drama callout. `prev_week_hitting`/`prev_week_pitching` are snapshot fields over the exact previous matchup Mon–Sun window — distinct from rolling `recent_hitting`(7d)/`recent_pitching`(15d) (fallback only). **`build_top_performers` also runs on `prev_week_*`** (subtitle shows the actual week dates; pitcher table shows **K** not G, ordered "by K"). **Both run names through `_fix_mojibake` before the season-roster lookup** — `prev_week_*` names arrive mojibaked, so without the fix the `_name_key` fallback misses the roster row and the player wrongly shows as a free agent. `_fix_mojibake` cleans TWO literal-backslash artifacts: `\xNN` escapes (`Eury P\xc3\xa9rez` → `Eury Pérez`) AND backslash-escaped apostrophes (`Ryan O\'Hearn` → `Ryan O'Hearn`, which carries no `\x` so it's cleaned before the `\x` early-out). The apostrophe cleanup is load-bearing since the shared canonical `_name_key` PRESERVES apostrophes — an uncleaned `O\'Hearn` would miss the roster row. Sidebar cards: fantasy logo + MLB team logo (`_mlb_logo`, ESPN CDN) + slash line / K / QS / categories led. Roto weekly win count = weekly top-roto-score count, NOT H2H W-L. MLB abbrev from season rows' `Team` field; `_MLB_ABBREV_ESPN` maps Baseball Reference outliers (TBR→tb, KCR→kc, SFG→sf, WSN→wsh, etc.).

- **`_recap_pitcher_rank_key(r)`** (module-level, shared by `build_top_performers`'s rostered/FA pitcher ordering AND `build_commissioner_story`'s Pitcher-of-the-Week/FA-Pitcher-of-the-Week picks) — `(-K, ERA, WHIP)`: raw strikeout count dominates completely, ERA/WHIP only break ties among pitchers with the same K total. **Deliberately NOT** the shared `fantasy.scoring.pitcher_score`/`rp_score` model (which still weighs ERA+WHIP roughly 2:1 over K) — this is a recap-narrative-only preference (user explicitly favors Ks over ratios for "best pitcher" call-outs), so it does not touch pitcher scores/badges anywhere else in the app. All three consumers (rostered table, FA table, both prose picks) share the one key so the recap never contradicts itself about who the best pitcher was.
- **FA Batter of the Week + FA Pitcher of the Week** (`fa_potw_bat`/`fa_potw_pit`) are separate picks from separate pools (`fa_h` by OPS, `fa_p` by `_recap_pitcher_rank_key`), each with its own paragraph + sidebar card ("Best Available Bat" / "Best Available Arm"). The FA-batter ladder deliberately avoids shaming language ("indictment of every manager who passed") — every free agent was, tautologically, passed on by every manager, so that framing was cut; replaced with neutral-enthusiastic phrasing.
- **"Matchup of the Week"** — scans ALL matchups that week (via `_dedup_matchup_pairs`, shared with `build_league_scoreboard`'s de-dup so a pair isn't double-counted) and calls out whichever was most dramatic: the most lopsided record (`_matchup_margin` ≥ 6 of 12 categories) as a blowout, and/or the closest (`_matchup_margin` ≤ 1) as a nailbiter — citing one real standout category either way (`_standout_category`, respecting `lower_better`). League-wide by design (not just the user's own matchup), since the recap is already full-league in scope. Silent when no matchup crosses either threshold.
- **Phrasing variety is deterministic, not wall-clock random.** Every hard-coded benchmark ladder (hitter OPS tiers, pitcher ERA/K tiers via the shared `_pitcher_benchmark_clauses` helper, position-scarcity flavor via `_position_scarcity_clause`, the roto-winner opener, FA tiers) picks from 2+ phrasings via `_pick(rng, choices)`, where `rng = _seeded_rng(week, player_name, tag)` hashes stable per-item data with `zlib.crc32` (NOT Python's salted `hash()`). Same snapshot → same picks, every run — required because `weekly_recap.py` is one of `scripts/render_diff.py`'s golden-baseline targets; a wall-clock-seeded RNG would make every run look like a regression. The roto-winner opener also varies its FRAMING (not just wording) based on the real margin over 2nd place (landslide ≥ 8 pts vs. squeaker ≤ 2 pts vs. a plain win in between) — a data-driven dimension, not just a reworded template.

**`build_league_scoreboard`** (`weekly_recap.py`) — all 6 matchups, one card each, 12-cat grid. Each team's identity (logo + name + W–L–T) lives in its **row label** (first column), NOT a top banner. Every card is a **separate `<table>`** using `table-layout:fixed` + a `<colgroup>` (150px label col + 12 equal cat cols) so the label→category axis lines up card-to-card. Long names ellipsis-clip. Category headers are **neutral** (`MUTED`), not green/red (even-handed full-league view); the **outlined value** (`outline:1px solid`) marks each category's winner. `_row` renders both teams (top = `my_team`/`my_val`, bottom = `opp_team`/`opp_val`).

**`build_lineup_efficiency`** (`weekly_recap.py`) renders `lineup_efficiency` (prev matchup) as a **LINEUP EFFICIENCY** band after My Matchup: red "LEFT ON THE BENCH" net headline, per-player bench cards (each notable day + swap target `[vs Name H-AB]`/`[open slot]`), a **"STARTS LEFT ON THE BENCH"** K/QS/W headline + per-pitcher benched-start cards (from `bench_sp`, each start line + `[open slot]`/`[vs Name IP]`), active-slot blowups with the drop flag, then an **"IDLE — WASTED ACTIVE SLOTS"** group. **`build_bench_watch`** (`send_digest.py`) renders `lineup_efficiency_current` (matchup-to-date) as the compact **Lineup Watch** callout (section 1b, after `alert_section`) — net-recoverable batter line + a **benched-SP line** (`+N K · +1 QS · +1 W from starts left on your bench`, ALL net-positive benched pitchers — no cap; the digest/dashboard row list mirrors the recap's uncapped list, aggregated as "K · QS · W across N starts" when multi-start) + implode-then-drop pitchers + a "Wasting active space" idle-hitter line (top 3); silent on a clean matchup; header "matchup to date". Gated on `not override_team` (snapshot stores only MY daily lineup).

### Layout: 1100px shell, 2-column condensing

`build_recap`'s HTML shell is `max-width:1100px` (widened from 760px so richer narrative content — the FA batter/pitcher split, Matchup of the Week — doesn't turn the email into an endless scroll). Same HTML serves both the inline body and the attachment (`send_email(html, html, ...)`, no separate short body like the digest's Briefing), so the width applies everywhere the recap is read. The existing `@media (max-width:600px)` query still forces `.ew` back to `width:100% !important` on phones — unaffected by the desktop max-width change.

Two sections that are stacks of structurally-uniform cards now render **2-column** instead of one-per-row, using the email-safe `_two_col(left, right)` `<table>` idiom (not CSS flex/grid, for email-client compatibility):
- **`build_league_scoreboard`** — all 6 matchup cards pair into 3 rows via `_two_col`, blindly in given order (cards are identical shape, no waterfall risk). The per-card inner table was trimmed (`min-width:520px`→`460px`, label column `150px`→`110px`) so a paired card fits inside one `_two_col` cell (~515px at the 1100px shell) without triggering its own `overflow-x:auto` scrollbar.
- **`build_lineup_efficiency`** — the `bench`/`bench_sp`/`blowups`/`idle` card groups each go 2-column via a new helper, **`_balance_two_columns(weighted_htmls)`** (next to `_two_col`): greedily assigns each `(weight, html)` block to whichever column has the smaller running weight, so variable-height cards (bench/bench_sp cards grow with `len(days)`) don't waterfall — mirrors `dashboard.py`'s own independent-column tile-packing solution to the identical uneven-card-height problem, reimplemented with this file's table markup. Weight = `1 + len(days)` for bench/bench_sp, `1` (uniform) for blowups/idle. The two headline alert banners (net-recoverable bat / starts-left-on-bench) stay full-width, unpaired — they're one-off summary callouts, not card lists. Other sections (Standings, Weekly Roto Rankings, My Matchup, Season Trajectory/Roto Rankings, Top Performers) are single wide grid tables or already 2-column via `_two_col` for a different axis (hitters vs. pitchers) — they benefit from the wider shell as-is and weren't restructured.
